# parse5 adoption — element-system repair EL-06

- Exact direct package: `parse5@7.3.0`, `packages/components` runtime dependency; existing lock entry reused. Added using cached pnpm 10.28.2 with `--save-exact --offline`; no other dependency adopted.
- Local metadata inspected: `node_modules/.pnpm/parse5@7.3.0/node_modules/parse5/package.json`: MIT; ESM `dist/index.js`, CJS `dist/cjs/index.js`; types `dist/index.d.ts`; dependency `entities ^6.0.0`. Upstream source: https://github.com/inikulin/parse5.
- Runtime: parser is pure JavaScript, operates without DOM/browser I/O, and works in browser Vite/Remotion bundles and Node. It is not a server process and makes no network requests. The browser composition remains the sole preview/export renderer.
- Why: the previous `dangerouslySetInnerHTML` passed arbitrary authored markup straight to React. Parsing an HTML AST correctly handles malformed markup/entities/foreign namespaces; regex substitution cannot establish that boundary. No existing component supplied an HTML parser/sanitizer.
- Bundle/tree shaking: named ESM `parseFragment` import permits bundler tree shaking; the tokenizer/parser and entity decoding tables are required, so this adds code to the composition/editor bundle. No unsupported precise size claim is made. Final production build and its emitted size output belong to Task5.
- Security: parser output is never trusted directly. A separate emitter outputs only documented static HTML tags, escaped text and explicitly validated style declarations. All attributes except filtered style are discarded; no URL-bearing attribute is emitted. Active elements, foreign namespaces and their descendants are discarded. CSS escapes, at-rules, resource functions and non-allowlisted properties are discarded. No network vulnerability audit was run; successful parsing alone is not sanitization.
- Exit: `sanitizeStaticHtml(string):string` isolates parser use in one module. A replacement parser must pass the same malformed-markup, namespace, attribute, CSS and formatting tests. Authored markup remains unchanged in project props, so replacement does not require archive/schema migration.

Static subset: div/p/span, b/strong/i/em/u/s/small/sub/sup, br/hr, blockquote/pre/code, ul/ol/li and h1–h6. Supported styles: color/background-color (named/hex/rgb/hsl), font-size/letter-spacing/line-height/padding/margin/border-radius (nonnegative unit values), font-weight, font-style, text-align, text-decoration and white-space. Other tags unwrap their text unless active/foreign; links have no navigation and images/media are omitted. Arbitrary CSS, classes, layouts, image URLs and embedded media are intentionally outside this subset. The existing HTML element's outer positioning/size remains ordinary typed component props.
